# GridNode Hardware Adapter Guide

GridNode is designed to be hardware-agnostic. While it defaults to GivEnergy via MQTT, you can add support for any inverter or battery system (Tesla Powerwall, Victron, Solis, etc.) by creating a new **Adapter**.

## The Adapter Architecture

The `gridnode-client` uses a dynamic loading system. When the client starts, it checks the `ADAPTER_TYPE` in your `.env` file and loads the corresponding class from the `src/adapters/` directory.

### 1. Create the Adapter File
Create a new file in `gridnode-client/src/adapters/`, for example: `teslaAdapter.js`.

### 2. Implement the Interface
Every adapter must implement two methods: `connect()` and `readMetrics()`.

```javascript
// gridnode-client/src/adapters/teslaAdapter.js

export class TeslaAdapter {
    constructor(config) {
        // Use variables from process.env here
        this.apiUrl = process.env.TESLA_API_URL;
        this.token = process.env.TESLA_ACCESS_TOKEN;
        this.latest = {};
    }

    /**
     * Initialize connection to the hardware (API, Modbus, or MQTT)
     */
    async connect() {
        console.log('[Tesla] Authenticating with Powerwall API...');
        // Implementation logic here
        return true;
    }

    /**
     * Fetch and return data in the GridNode Standard Format
     */
    async readMetrics() {
        // 1. Fetch raw data from your source
        // 2. Map it to the return object below
        return {
            houseLoad: 450,          // Watts (Integer)
            p_battery: -1200,        // Watts (Negative = Discharging, Positive = Charging)
            soc: 85,                 // Percentage (0-100)
            batteryCapacityKwh: 13.5, // Total battery size
            energyRemainingKwh: 11.4, // Current usable energy
            solarTodayKwh: 5.2,      // Accumulated solar for the day
            storageTodayKwh: 8.1,    // Accumulated battery charge for the day
            dischargeRate: 1200,     // Current discharge speed in Watts
            reserve: 200,            // Watts reserved for backup
            regionStatus: 'stable'   // Optional: 'stable', 'warning', or 'critical'
        };
    }
}
```

## Standard Data Mapping

To ensure the Hub dashboards and Cluster Map work correctly, ensure your `readMetrics` output follows these units:

| Field | Unit | Description |
| :--- | :--- | :--- |
| `houseLoad` | **Watts** | Total power currently consumed by the building. |
| `p_battery` | **Watts** | Power flow to/from battery (Negative is grid-support mode). |
| `soc` | **%** | State of Charge (0 to 100). |
| `batteryCapacityKwh`| **kWh** | The total size of the battery array. |
| `energyRemainingKwh`| **kWh** | Calculated as: `(soc / 100) * capacity`. |
| `solarTodayKwh` | **kWh** | Energy generated by PV since midnight. |
| `storageTodayKwh` | **kWh** | Energy stored into the battery since midnight. |

## 3. Register the Adapter

Open `gridnode-client/src/index.js` and add your new case to the `switch` statement inside the `main()` function:

```javascript
// gridnode-client/src/index.js

async function main() {
    let adapter;

    switch (config.adapterType) {
        case 'givenergy-mqtt':
            const { MqttAdapter } = await import('./adapters/mqttAdapter.js');
            adapter = new MqttAdapter({ brokerUrl: config.mqttBrokerUrl });
            break;

        case 'tesla':
            const { TeslaAdapter } = await import('./adapters/teslaAdapter.js');
            adapter = new TeslaAdapter();
            break;

        default:
            throw new Error(`Unsupported adapter type: ${config.adapterType}`);
    }

    await adapter.connect();
    // ... rest of start logic
}
```

## 4. Configure .env

Change the adapter type in your node's configuration to use the new controller:

```bash
# gridnode-client/.env
ADAPTER_TYPE=tesla
TESLA_API_URL=https://owner-api.teslamotors.com
TESLA_ACCESS_TOKEN=your_token_here
```

Your node will now report data from your new hardware source while remaining fully compatible with the GridNode mesh.
